How it works

Look first. Change one thing. Undo anything.

  1. 01

    See everything it loads.

    harn reads your agent's config without starting a session, Claude Code's settings layers or Codex's config.toml layers, and groups what lands in the first request by kind: the skill listing, project files, plugins, hooks, built-ins and more, each with its size, a bar and its share. What files cannot size reads unmeasured; harn verify --run measures what the agent's own view of the first request shows.

  2. 02

    Know where each item comes from.

    Press w on any row: the settings file and key that turn it on, where it was installed from, the files on disk, and everything it contributes.

  3. 03

    Turn one off with one card.

    Press d: one card says which file it writes, what leaves with it (→ lists every item), what it saves and how to undo. Enter applies, Esc cancels. harn only uses the agent's official switches, never a wider scope silently. For Claude Code it writes a settings key to .claude/settings.local.json, for this project. For Codex it writes the item's own key to the narrowest config.toml Codex reads: the folder's .codex/config.toml when Codex trusts the folder, otherwise ~/.codex/config.toml, which every project reads. The card names the file and the key.

  4. 04

    Undo, byte for byte.

    harn snapshots the file before every write and journals the change. u undoes the last one, o turns an item back on, and harn undo works later from the shell. The file comes back byte for byte.

  5. 05

    Or let your agent trim.

    harn trim asks your coding agent for a plan in one headless request, with no tools and one turn. It validates the plan, prints each change with the agent's reason and the bytes it frees, and applies only when you answer y. Inside Claude Code, /harn-trim runs the same loop. harn trim works with Claude Code for now; for Codex it refuses.

Principles

  • Official switches onlyA settings key the agent already reads, never a wider scope silently.
  • Reversible byte for byteA snapshot before every write; harn undo puts it back.
  • --readonly refuses every writeAnd every active verify. The screen says so in its header.
  • Looks without starting a sessionIt reads files. Your agent starts only on harn trim or harn verify --run.
  • No network from harn itselfThe binary has no network code.

Questions

What it touches, and what it doesn't.

What does it change on disk?

Nothing until you ask. When you turn something off, harn sets one official key, never a wider scope silently. For Claude Code it is a settings key, by default in .claude/settings.local.json for this project only. For Codex it is the item's own key in the folder's .codex/config.toml when Codex trusts the folder, else in ~/.codex/config.toml. It snapshots the file first and journals the change (harn history).

How do I undo?

u on the screen undoes the last change, o turns an item back on, and harn undo works from the shell. Each one restores the file byte for byte.

Does it start your agent?

No. It reads the config layers and sizes what files can size. Claude Code starts on two commands: harn trim (one headless request for a plan) and harn verify --run (one real session, which may cost one model request). For Codex, harn verify --run runs four of Codex's inspection commands: no model request, but codex debug prompt-input starts your MCP servers and may write into ~/.codex.

Does it send anything anywhere?

harn itself has no network code. harn trim and harn verify --run start your own agent, which talks to its provider the way it always does.

What about Codex?

Yes. harn shows one tree per agent: Claude Code and the Codex CLI each get their own tab when they load something in the directory. For Codex it reads ~/.codex and the AGENTS.md files, and turns things off with Codex's own keys in config.toml.

Linux?

Yes. One binary for macOS and Linux, on Apple silicon, Intel and ARM. Homebrew works on both; Releases has the four binaries and their SHA256SUMS.

Know what you're sending.

One binary for macOS and Linux, through Homebrew on both. Or take a binary and its checksum from Releases.
